## Proposed Change

### Principle: Educational accuracy

> **18. Educational accuracy** — the explanatory copy on each demo page (headings, "How this pattern works", "Good for" / "Watch for", "How it's built", form messages) describes the implementation as it actually is. A change to either the copy or the behavior it describes keeps the other true in the same PR. *(adopting)*

**Rationale**: For an educational reference, the explanatory copy *is* the product. A false claim about how a pattern validates, saves or renders teaches the wrong lesson, and code review of `.cs` files will not catch it. PR #309 showed four such claims passing build, tests and runtime checks; only a manual read of copy against code found them.

**MUST Requirements:**

- Claims about this app's behavior (validation, redirects, persistence path, error handling, input rules) match the code that serves that page.
- Claims about a framework's internals (React, Vue, htmx, Blazor, etc.) are accurate for the version the page loads.
- A PR that changes a demo's behavior updates any copy on that page that describes it, and vice versa.

**SHOULD Recommendations:**

- A PR that rewrites demo copy lists, in its description, the controller, page model or component each changed claim describes, so review can check them side by side.
- Prefer describing observable behavior ("you return to the list") over evaluative claims ("seamless", "efficient") that cannot be checked.
- Where the demo deliberately simplifies (e.g. no server-side re-display of validation errors), say so on the page rather than describing the production-grade behavior.
